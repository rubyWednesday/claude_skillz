오늘 JIRA 워크로그를 추천하고 입력합니다.

## 사용법
`/worklog` — 오늘 날짜로 추천 및 입력
`/worklog yesterday` — 어제 날짜로 추천 및 입력

## 지시사항

### 1. 날짜 결정
- 인자 없으면 오늘 날짜 사용
- `yesterday` 인자면 어제 날짜 사용

### 2. 내 이슈 조회
`jira_my_issues`로 In Progress 이슈 목록 가져오기.
Closed 이슈는 제외.

### 3. 오늘 이미 입력된 워크로그 확인
In Progress 이슈들에 대해 `jira_get_worklogs_batch` 호출.
대상 날짜에 이미 입력된 워크로그가 있으면 해당 이슈와 시간을 메모해두고 중복 추천 피하기.
이미 입력된 워크로그 합산 시간도 계산해두기.

### 4. 최근 워크로그 패턴 파악
같은 배치 결과에서 최근 7일 워크로그를 확인해 다음을 파악:
- 자주 쓰는 이슈 (상위 2~3개)
- 코멘트 앞에 붙는 prefix 패턴 (예: `미래:개발자발의,`)
- 하루 평균 총 시간

### 5. 현재 스프린트 컨텍스트 파악 (선택)
자주 쓰는 상위 이슈 1~2개에 대해 `jira_get_issue` 호출.
이슈의 최근 스프린트 노트(customfield_35977 등)에서 이번 주 진행 중인 작업 항목 파악.
→ 워크로그 내용 추천에 활용.

### 6. 추천 생성
아래 기준으로 워크로그 항목 추천:

- **이슈**: 최근 자주 쓴 이슈 우선. 스프린트에서 진행 중인 항목 있으면 반영
- **내용**: 최근 코멘트 패턴(prefix 포함)을 따르되, 스프린트 진행 항목 기반으로 구체화
- **시간**: 하루 8h 기준. 이미 입력된 시간 빼고 나머지 배분. 이슈 수에 따라 균등 분할 (보통 4h+4h)

추천 테이블 형식으로 출력:
| # | 이슈 | 내용 | 시간 |
|---|------|------|------|
| 1 | TVPLAT-XXXXXX | `[내용]` | Xh |
| 2 | TVPLAT-XXXXXX | `[내용]` | Xh |

이미 입력된 워크로그가 있으면 먼저 보여주기:
> 오늘 이미 입력: TVPLAT-XXXXXX 4h, TVPLAT-XXXXXX 2h (합계 6h) → 잔여 2h

### 7. 확인 후 입력
추천 출력 후 사용자에게 확인 요청.
- "이대로 입력할까요? (수정 원하면 알려주세요)" 라고 물어보기
- 사용자가 승인하거나 수정사항 주면 `jira_add_worklogs_batch`로 입력
- started 시간: 첫 항목은 09:00, 이후 항목은 순서대로 배분 (4h 간격)

### 8. 완료 메시지
입력 완료 후 입력된 항목 목록 간단히 출력.
